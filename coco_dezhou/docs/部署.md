# 部署：把牌桌放到公网

## 先说结论：Aternos 不行

`https://zzjj123.aternos.me/` 是 **Aternos 免费 Minecraft 服务器**的地址，它只提供"跑 Minecraft 服务端"这一件事：

- 只能上传 **Minecraft 服务端 / 插件 / 模组**，没有 Node.js 运行时，也没有 SSH、没有自定义进程；
- 只对外开放**游戏端口**（默认 25565），不能给你一个 HTTP/WebSocket 端口；
- 服务器**没人就自动停**，还要排队启动；故意保活/绕限制违反其条款；
- [Aternos 服务条款](https://aternos.gmbh/en/aternos/terms) §5.2 明确禁止"上传/下载外部可执行文件"、"用机器人伪造活跃"、"绕过空闲停止"，§5.1 要求只能按其用途使用。

所以它承接不了这个德州扑克服务（本项目需要：常驻 Node 进程 + 一个可访问的 HTTP 端口 + WebSocket）。

---

## 这个应用对托管的最低要求

| 要求 | 说明 |
| --- | --- |
| 运行时 | Node.js ≥ 20（或直接跑 Docker 镜像） |
| 常驻进程 | 房间状态在内存里，**不能用 Serverless / 函数计算**（它们不支持长连接，也会随时冷启动） |
| 协议 | 必须支持 **WebSocket**（Vercel、Netlify Functions、Cloudflare Workers 都不支持） |
| 端口 | 一个 TCP 端口即可（默认 18080，平台一般用 `PORT` 注入） |
| 资源 | 极低：50–100 MB 内存，几乎不吃 CPU |
| HTTPS | 建议 https（页面用 https 时前端会自动切 `wss://`） |
| 存储 | 可选，`DATA_DIR` 挂卷可长期保留战绩 |

## 四种可行方案

| 方案 | 成本 | 适合 | 坑 |
| --- | --- | --- | --- |
| **1. 内网穿透**（Cloudflare Tunnel / cpolar / ngrok） | 免费 | 想今天就让外地朋友玩 | 电脑要一直开着 |
| **2. 免费 PaaS**（Render / Hugging Face Spaces） | 免费 | 想 7×24 在线又不想运维 | 空闲会休眠、冷启动 30–60s、无持久磁盘 |
| **3. 云服务器**（腾讯云轻量 / 阿里云 ECS） | 约 ¥24–40/月 | 长期玩、国内访问快 | 国内域名 https 需备案（可先用 IP+端口） |
| **4. 家里旧手机 / IPv6 + DDNS** | 免费 | 折腾党 | 运营商可能不给公网 v4 |

## 方案 1：内网穿透（最快，5 分钟）

电脑继续 `npm start`，用 Cloudflare Tunnel 把本地 18080 暴露成公网 https 地址：

```bash
# 安装 cloudflared 后（Windows 用 winget install Cloudflare.cloudflared）
cloudflared tunnel --url http://localhost:18080
```

它会打印一个 `https://xxxx.trycloudflare.com` 地址，直接发给朋友即可（https 页面会自动用 `wss://`，不用改代码）。
临时域名每次重启会变；想要固定域名就申请一个 Cloudflare 账号做命名隧道。

同类工具：`cpolar`（国内速度好）、`ngrok`、自建 `frp`。

> 注意：电脑休眠/关机牌桌就断了；房间在内存里，重启会清空（战绩仍保留在 `data/hands.jsonl`）。

## 方案 2：免费 PaaS（本方案的重点）

先说清楚免费档的"真相"，免得踩坑：

| | Render 免费 | Hugging Face Spaces 免费 |
| --- | --- | --- |
| 要信用卡吗 | 不要 | 不要 |
| 休眠规则 | 15 分钟没有流量 → 休眠，下次访问冷启动约 30–60 秒 | 约 48 小时无人访问 → 休眠 |
| 免费额度 | 每个工作区每月 750 实例小时（单个服务 7×24 约 744 小时，刚好够） | CPU Basic（2 vCPU / 16GB）不限时 |
| 持久磁盘 | 免费档**没有**（重启后 `data/` 清空） | 免费档**没有** |
| WebSocket | 支持 | 支持 |
| 地址 | `https://xxx.onrender.com`（可绑自己域名） | `https://用户名-space名.hf.space` |
| 适合 | 想长期在线、要能绑域名 | 最省事，拖文件就能上线 |

两个共同点：**房间在内存里，休眠/重启后就没了**；战绩 `data/hands.jsonl` 也不会保留。对"约朋友打一晚上"的用法完全没影响。

### 2.1 Render（推荐）

仓库里已经带了 [`render.yaml`](../render.yaml)，用 Blueprint 一步到位：

1. 把项目推到 GitHub（public 或 private 都行）；
2. 打开 [render.com](https://render.com) → 注册 → **New → Blueprint** → 选这个仓库；
3. Render 自动读到 `render.yaml`：Docker 构建、免费档、健康检查 `/api/health`，点 **Apply**；
4. 等 2–3 分钟构建，访问 `https://<服务名>.onrender.com/api/health`，看到 `{"ok":true,...}` 就成了；
5. 手机打开 `https://<服务名>.onrender.com` 建房间即可。

不想用 Blueprint 也可以手动：**New → Web Service → 选仓库**，Runtime 选 **Docker**，其余默认。

#### 如果项目在仓库的子目录里（monorepo）

Render 只会在**仓库根目录**找 `render.yaml`。如果你的仓库长这样：

```
你的仓库/
├─ README.md
└─ coco_dezhou/          ← 本项目在这里
   ├─ render.yaml
   ├─ Dockerfile
   ├─ server/ shared/ web/
```

有两种做法：

**做法 1：不用 Blueprint，手动建（不改仓库，最快）**

New → **Web Service** → 选仓库 → 展开 **Advanced**：

| 字段 | 填什么 |
| --- | --- |
| Root Directory | `coco_dezhou` |
| Runtime | `Docker` |
| Instance Type | `Free` |
| Health Check Path | `/api/health` |

点 Create 即可（Root Directory 决定了 Dockerfile 去哪里找）。

**做法 2：在仓库根目录放一个 `render.yaml`**

在 GitHub 仓库首页 → Add file → Create new file → 文件名 `render.yaml`，内容：

```yaml
services:
  - type: web
    name: coco-dezhou
    runtime: docker
    plan: free
    rootDir: coco_dezhou        # ← 关键：告诉 Render 项目在子目录
    dockerfilePath: ./Dockerfile
    healthCheckPath: /api/health
```

提交后回到 Blueprint 页面点 **Retry**（Blueprint Path 留空即可）。

> 空闲休眠后，第一个访问的人会看到约 30–60 秒的白屏（Render 的唤醒页），之后就正常了。
> 想避免"朋友打开要等"，可以启用仓库里自带的 [`.github/workflows/keepalive.yml`](../.github/workflows/keepalive.yml)：在 GitHub 仓库 Settings → Variables 里加 `APP_URL`，它会每 10 分钟 ping 一次。**建议只在约局时段前后开启**，长期保活会吃掉 750 小时额度。
>
> ⚠️ GitHub 只承认**仓库根目录**的 `.github/workflows/`。如果本项目放在子目录（例如 `coco_dezhou/.github/workflows/`），需要把这个 workflow 文件复制到仓库根目录的 `.github/workflows/keepalive.yml` 才会生效。

### 2.2 Hugging Face Spaces（免费额度最宽松、最省事）

不需要 Git、不需要信用卡，网页拖文件即可：

```bash
npm run hf          # 生成 dist/hf-space（Dockerfile + 源码 + 带 sdk:docker 头的 README）
```

1. 打开 [huggingface.co/new-space](https://huggingface.co/new-space)，SDK 选 **Docker** → **Blank**；
2. 把 `dist/hf-space` 里的**全部文件**（含 `README.md`、`Dockerfile`、`server/`、`shared/`、`web/`）拖到 Space 的 **Files** 页面；
3. 等 **Build** 走完，打开 `https://<用户名>-<space名>.hf.space` 就能玩。

`README.md` 头部已经写好 `sdk: docker` 和 `app_port: 18080`（和 Dockerfile 里的 `PORT` 一致），不要删。

> 这个平台本体是 AI 演示站，用来放小游戏属于"能用但不主流"，介意的话走 Render。

### 2.3 备选平台

- **Zeabur**：部署 Git 仓库、自动识别 Dockerfile、自带 https，有免费/低消档；
- **Koyeb**：Web Service + Dockerfile，选最小的 nano 实例；
- **Railway**：体验最好但已没有长期免费档（$5 试用到头需要付费）。

以上都原生支持 WebSocket，用同一个 `Dockerfile` 即可。

### 2.4 免费档注意

- 单实例就好：房间状态在进程内存里，**不要开多副本/自动扩缩容**，否则两个人可能落在不同实例上；
- 免费实例没有持久磁盘，别把战绩当存档；需要长期保存就挂卷（付费）或用云服务器；
- 冷启动 30–60 秒属正常，唤醒后所有旧房号失效，重新开房即可。

## 方案 3：自己的云服务器

```bash
# 装 Node 20+（Ubuntu 示例）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 上传项目后
cd coco_dezhou
PORT=18080 DATA_DIR=/var/lib/dezhou node server/index.mjs
```

用 systemd 守护：

```ini
# /etc/systemd/system/dezhou.service
[Unit]
Description=DeZhou Poker
After=network.target

[Service]
WorkingDirectory=/opt/coco_dezhou
Environment=PORT=18080
Environment=DATA_DIR=/var/lib/dezhou
ExecStart=/usr/bin/node server/index.mjs
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now dezhou
```

想用域名 + https，用 Caddy 一行反代（自动签证书）：

```
poker.example.com {
    reverse_proxy 127.0.0.1:18080
}
```

> 国内服务器绑定域名走 https 需要备案；来不及备案就先用 `http://IP:18080` 直连（把 18080 加进安全组）。
> 手机上 http 页面也能玩，只是部分浏览器会提示"不安全"。

## 方案 4：旧手机 / 家庭宽带

- 安卓旧手机装 Termux，`pkg install nodejs`，跑本项目 + 内网穿透；记得关掉省电限制。
- 家里有 IPv6 公网地址时，可以用 DDNS 域名 + 放行端口，直接 `http://[IPv6]:18080`（朋友也要有 IPv6）。

## 上线后自检

一条命令把「健康检查 → REST 建房 → wss 进房 → 静态页」全跑一遍：

```bash
node tools/live-check.mjs https://你的地址
```

全部通过会打印：

```
  ✔ /api/health 正常（1114ms，版本 1.0.0）
  ✔ REST 创建房间成功：#949273
  ✔ wss 连接正常，进房成功（座位 1，房间 949273）
  ✔ 清理自检房间完成
  ✔ 首页可访问
结论：全部通过，可以开黑了。
```

也可以手动 `curl https://你的地址/api/health` 应返回 `{"ok":true,...}`。

最后手机打开 `https://你的地址/?room=房号` 走一遍"创建 → 加入 → 开局 → 出牌"。

**CoCo 打包**时，把「网页框」控件地址填成这个 https 地址即可；WebSocket 会自动走 `wss://`。
