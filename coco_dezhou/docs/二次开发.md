# 二次开发 / 修改指南

改之前先记住一句话：**这个项目有两份副本——GitHub 上的仓库（线上 Render 就是拿它构建的）和某个本地目录。** 先选定一个"真源"，否则改完两边对不上。

- 只在 GitHub 网页改 → **GitHub 是真源**，本地不用管；
- 在本地用 Git clone 改 → **本地是真源**，push 后自动上线；
- 让 AI 帮你改 → 它改的是本地目录，改完要把文件内容贴回 GitHub（或你本地 `git commit`）。

---

## 1. 三种改法，按上手成本排序

### A. GitHub 网页直接改（小改动首选，零安装）

1. 打开 `github.com/Tyrozj/dezhou_poker_app`，一路点进 `coco_dezhou/...` 找到要改的文件；
2. 右上角 **铅笔图标** → 直接改 → 右下 **Commit changes**（提交到 `main`）；
3. Render 会自动重新构建（Dashboard → **Events** 里能看到 `Deploy live`），2–3 分钟后刷新页面就是新版本；
4. 没自动部署就点 **Manual Deploy → Deploy latest commit**。

小技巧：把文件链接里的 `/blob/` 改成 `/edit/` 就直达编辑页，例如
`github.com/Tyrozj/dezhou_poker_app/edit/main/coco_dezhou/web/css/style.css`。

适合：改文案、改配色、调数字、改默认值。缺点：没有实时预览，改 JS 逻辑容易写错。

### B. 本地开发（反复调试首选）

```bash
git clone https://github.com/Tyrozj/dezhou_poker_app.git
cd dezhou_poker_app/coco_dezhou
npm run dev            # = node --watch server/index.mjs，改服务端代码自动重启
```

- 浏览器开 `http://localhost:18080`；
- **前端改动（html/css/js）刷新即生效，不用重启**——静态文件是每次请求时读盘的；
- 服务端改动由 `--watch` 自动重启（房间会清空，属正常）；如果所在环境不支持 `--watch`（个别精简/受限终端），就用 `npm start`，改完手动 Ctrl+C 再启；
- 手机预览：同一 Wi-Fi 下用电脑局域网 IP 访问；
- 满意后 `git add -A && git commit -m "xxx" && git push`，Render 自动上线。

### C. 让 AI 改

说清"改哪个页面/什么效果"即可。改完你可以：
- 让它把**改动文件的全文**贴出来，你在 GitHub 网页整段替换（最稳）；
- 或让它给出**逐处 diff**（改了哪几行、原样→新样），你在网页上照改。

## 3. 三个最常改的例子

### 例子 1：换主题色（纯前端，30 秒）

`web/css/style.css` 第 5–20 行：

```css
:root {
  --felt-a: #1e7455;   /* 桌面中间那张"绿" */
  --felt-b: #0b3a2a;
  --gold:   #e8c479;   /* 房号、筹码、强调色 */
  --red:    #d6413b;   /* 红桃方块、全下按钮 */
}
```

改完刷新即可。想整体换风格，改这 4 个变量就够。

### 例子 2：改默认盲注 / 起始筹码 / 思考时间

`server/table.mjs` 第 12 行：

```js
const DEFAULT_SETTINGS = {
  seats: 6,          // 默认 6 人桌
  startChips: 1000,  // 默认起始筹码
  sb: 10,            // 小盲
  bb: 20,            // 大盲
  actionSeconds: 25, // 默认思考时间
  ...
};
```

同时 `normalizeSettings()` 第 25–29 行有**允许范围**（例如人数只能 2–8、时间 10–120 秒），想让玩家能填更大的数就一起放宽：

```js
s.seats = clampInt(s.seats, 2, 9, 6);          // 允许 9 人桌
s.actionSeconds = clampInt(s.actionSeconds, 10, 180, 25);
```

> 改人数上限别超过 `SEAT_POS` 里已有的套数（2–8），否则第 9 个座位没坐标、会挤在一起。

### 例子 3：把 6 位房号改成 4 位

要同步改 4 处，漏一处就会出 bug：

| 文件 | 位置 | 改成 |
| --- | --- | --- |
| `server/rooms.mjs` | `newCode()`：`100000 + randomInt(900000)` | `1000 + randomInt(9000)` → 4 位 |
| `web/js/app.js` | `const code = (...).replace(/\D/g,'')` 后的 `length !== 6` | `length !== 4` |
| `web/index.html` | `<input id="code-input" maxlength="6">` | `maxlength="4"` |
| `web/js/app.js` + `index.html` | 提示文案"输入 6 位房号""请输入 6 位房号" | 改成 4 位 |

## 4. 上线与回滚

- **自动**：push 到 `main`（或网页 Commit）→ Render 自动构建部署；
- **手动**：Render Dashboard → 服务 → **Manual Deploy → Deploy latest commit**；
- **回滚**：Render → **Events** 里找到上一个 `Deploy live` → **Rollback to this deploy**；或者 `git revert` 后 push；
- **看日志**：Render → **Logs**，启动失败会直接打印堆栈。

改完线上自检一条命令：

```bash
node tools/live-check.mjs https://dezhou-poker-app.onrender.com
```

## 5. 改完的自测清单

本地（或线上）各开两个浏览器窗口——**一个正常、一个无痕模式**（否则共用 localStorage 会互相顶号）：

- [ ] 建房 → 第二个人输房号进房，两边座位/筹码一致；
- [ ] 翻前跟注 → 翻牌 → 转牌 → 河牌能走完，摊牌能亮牌并显示赢家；
- [ ] 加注面板：最小/½池/满池/全下 四个按钮值都不越界；
- [ ] 一个人关掉页面再打开，能自动回原座位；
- [ ] 房主退出后，房主自动转给另一个在线玩家。

服务端逻辑改动，再跑一遍：

```bash
npm test        # 18 项：牌型 / 引擎 / 端到端
```

## 6. 注意事项

- **别同时改两边**：网页改完，本地那份就是旧的；下次谁覆盖谁都不好说。真源只有一个。
- **`data/` 不要提交**（已在 `.gitignore`）；线上免费实例没有持久磁盘，战绩重启即丢。
- **不要开多实例/自动扩缩容**：房间状态在内存里，多副本会让人落在不同进程上看不到彼此。
- **改 `server/table.mjs` 要格外小心**：下注合法性、边池分摊都在这里，`npm test` 是最低保障。
- **改协议**（`docs/协议.md` 里的字段）时，`server/index.mjs`、`web/js/app.js`、CoCo 积木那边的调用要一起改。
